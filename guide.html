현재 데모에서 하는 일

방문자가 용도를 자유롭게 적으면 Gemini가 필요한 조건을 추출합니다. 견적 서비스는 판매 카탈로그에서 그 조건에 맞는 서버와 장착 가능한 부품을 찾습니다.

홈페이지 제품 목록 1,553종과 확장 카탈로그를 함께 검색합니다. 호환 부품이 등록된 354종은 802개 기본 구성에서 견적을 만들 수 있습니다. 제품번호와 부품번호, 제품 사진, 교육 영상, PDF 원문을 조회할 수 있습니다. Gemini는 질문과 앞서 확인한 조건, 카탈로그에서 찾은 후보 구성을 검토합니다. 견적서에서 선택한 부품과 제조사 사양 링크를 확인할 수 있습니다.

운영 상담은 회사 PDF 110개, 1,143쪽의 본문을 검색하고 관련 페이지를 연결합니다. 아래의 File Search는 제조사 문서에 근거한 기술 질의응답을 추가할 때 사용할 수 있는 설계입니다. 이 데모의 카탈로그는 아직 Google File Search에 등록하지 않았습니다.

What the live demo does today

Gemini interprets a workload in the visitor’s own words. The quote service checks those requirements against catalog systems and compatible components.

Search the company product catalog, part numbers, photos and videos. Quotes are generated for 354 systems with 802 validated base configurations. The document index covers 110 PDFs and 1,143 pages.

Scale discovery, compatibility checks and quote generation are live. File Search, described below, is a proposed extension for source-backed technical answers. This demo’s catalog has not been indexed in Google File Search.

사양서를 한 번 등록하고 계속 질문하기

Gemini File Search에 제품 설명과 사양서를 등록하면 Google이 문서를 작은 단위로 나눠 의미 검색용 색인을 만듭니다. 이후 API 요청은 질문과 검색 저장소 ID를 전달합니다. Gemini는 질문과 관련된 부분을 찾아 읽고, 답변에 사용한 파일의 출처를 돌려줄 수 있습니다.

  1. 모델별 자료를 준비합니다. 모델 번호, 세대, 보드 리비전, 문서 개정일, 출처를 함께 기록합니다. 한 제품군의 브로슈어와 특정 모델의 사양서는 별도 문서로 구분합니다.
  2. 색인을 만듭니다. PDF와 정리된 제품 설명을 File Search 저장소에 넣고 처리 완료를 확인합니다. 다음 상담에서도 같은 저장소를 사용할 수 있습니다.
  3. 질문과 근거를 연결합니다. “메모리를 어디까지 늘릴 수 있나요?”라는 질문에는 선택 모델과 CPU 세대를 함께 사용해 검색하고, 해당 조건이 표시된 사양표를 근거로 답합니다.

가중치가 같은 Gemini 모델이 여러 상담에서 같은 지식 저장소를 참조하는 방식입니다. 일반 파일 업로드의 임시 파일과 File Search에 가져온 검색 색인은 보존 방식이 다릅니다. Google의 File Search 동작 원리 ↗

Index specifications once and reuse them

Gemini File Search breaks product descriptions and specifications into searchable passages. Subsequent API calls identify the store and supply the question. Gemini can retrieve relevant passages and return citations for its answer.

  1. Prepare model-level documents. Record the SKU, generation, board revision, document revision and source. Keep family brochures distinct from individual model datasheets.
  2. Create the index. Import the PDFs and normalized descriptions into a File Search store and check processing has completed. Future conversations use the same store.
  3. Ground each answer. For a memory-capacity question, use the selected system and CPU generation to retrieve the applicable section of the specification.

The model’s weights stay the same while many conversations consult the shared knowledge store. Temporary uploaded files and the imported search index have different retention rules. How Google File Search works ↗

Four methods and their roles

Find the relevant explanation · File Search

A question about air-cooled inference servers can retrieve the relevant passage in an English installation guide. Model datasheets, installation instructions and white papers fit this workflow. File Search documentation ↗

Check exact constraints · Database tools

An agent can ask the service for compatible DIMMs or GPU servers approved for sale. Gemini selects the search conditions, the service returns matching rows, and Gemini explains the trade-offs. Use structured data for quantities, slot counts, CPU-dependent memory limits and sales eligibility. Gemini function calling ↗

Teach a consultation style · Fine-tuning

On a supported model, curated question-and-answer pairs can teach a preferred discovery sequence or quote format. Keep changing compatibility and sales records current in a separate database. Preparing training examples on Google Cloud ↗

Reuse a repeated input · Context caching

Repeated long instructions or common input can benefit from caching. Eligibility, cost and latency benefits depend on the API, model and cache hit. A search index selects passages across a large document collection. Gemini context caching ↗

견적은 어떤 기준으로 검토하나요?

  1. 사용 조건. 전체 직원 수, 동시에 일하는 사람이나 에이전트 수, 모델 크기와 운영 시간을 구분합니다. 이미 입력한 조건은 다음 요청에도 적용합니다.
  2. 부품과 설치. 판매 목록의 모델과 부품 번호, 수량, 제조사 필수 옵션을 확인합니다. 서버당 노드 수와 서버 대수를 곱해 전체 부품 수량을 계산합니다. 전용 랙이 필요한 모델에는 설치 조건을 표시합니다.
  3. 운영 성능. 500B 모델의 BF16 가중치는 약 1,000GB입니다. 여유 25%를 더한 1,250GB는 500B 기준의 메모리 산정값입니다. 20~30개 코딩 에이전트가 24시간 가동될 때 필요한 대수는 실제 모델과 문서로 검색과 생성을 함께 실행하고, 첫 토큰 지연(p95), 요청별 생성 속도, 오류율을 측정해 결정합니다. NVIDIA 추론 지표 ↗
  4. 예산. 예산은 내부 선정 기준으로 사용합니다. 요청과 차이가 있으면 가까운 서버의 모델명, 수량, 달라진 사양을 견적서에 함께 표시합니다. 가격 정보는 비공개입니다.

How is a quote reviewed?

  1. Workload. Staff, concurrent users or agents, model size and operating hours are recorded separately and carried into follow-ups.
  2. Hardware and installation. The service checks catalog part numbers, quantities and installation requirements. The total bill accounts for nodes per chassis and system count. Rack-level requirements appear on the quote.
  3. Performance. A 500B model has approximately 1,000 GB of BF16 weights. Adding 25% gives a planning figure of 1,250 GB for that model size. To size 20–30 coding agents running around the clock, test retrieval and generation together using the actual model and documents. Measure p95 time to first token, per-request output rate and errors. NVIDIA inference metrics ↗
  4. Budget. Your budget informs the internal selection. Where a configuration differs from your request, the quote lists the alternative model, quantity and differences. Pricing is private.

기술 질문에는 조건과 출처가 함께 필요합니다

“AS-1115CS-TNR에 메모리를 3TB까지 넣고 6400MT/s로 쓸 수 있나요?”

제조사 사양표에는 DIMM 슬롯 12개, 최대 3TB가 기재돼 있습니다. EPYC 9004 구성은 최대 4800MT/s이며, EPYC 9005 구성은 보드 R2.0에서 최대 6000MT/s, R2.01에서 최대 6400MT/s입니다. 같은 모델 번호라도 CPU와 보드 리비전을 함께 확인해야 답이 정해집니다. Supermicro 공식 모델 사양 · System Memory ↗

문서 검색을 연결한 에이전트라면 이 사양표를 인용한 뒤, 해당 CPU·보드 조합에서 실제 견적 가능한 DIMM 부품 번호를 회사 DB로 확인할 수 있습니다. 보드 리비전이 빠져 있으면 그 조건을 사용자에게 묻거나 확인 필요로 표시합니다.

Technical answers need conditions and a source

“Can an AS-1115CS-TNR run 3 TB of memory at 6400 MT/s?”

The manufacturer lists 12 DIMM slots and up to 3 TB. EPYC 9004 configurations are specified up to 4800 MT/s. With EPYC 9005, revision R2.0 is listed up to 6000 MT/s and R2.01 up to 6400 MT/s. Both the CPU and board revision matter. Supermicro system memory specifications ↗

An advisor with document retrieval can cite this specification, then query the company catalog for orderable DIMM part numbers. A missing board revision becomes a follow-up question or an explicit condition on the answer.

새 제품이 들어오면 무엇을 갱신할까?

  • 사양서가 바뀌면 SKU와 문서 개정일, 파일 해시로 변경을 찾고 새 문서를 색인한 뒤 구버전을 검색 대상에서 뺍니다. 검색 저장소 전체를 매번 다시 만들 필요가 없습니다.
  • 공급 품목이 바뀌면 판매 승인 여부와 모델별 호환 부품표를 갱신합니다. 공개 데모는 빌드할 때 승인 카탈로그를 포함하므로 새 견적 데이터는 다음 배포에 반영됩니다.
  • 답변 속도를 관리할 때는 최초 색인 시간, 질문당 검색 시간, Gemini 답변 생성 시간을 나눠 측정합니다. 색인이 있으면 질문마다 전체 PDF를 전송하는 비용을 줄일 수 있습니다. 검색된 단락의 입력 토큰과 답변 생성 시간은 여전히 필요합니다. Google File Search 비용 안내 ↗

AIK에 적합한 확장안은 문서 검색과 판매 DB 조회를 함께 쓰는 구성입니다. 설명에는 제조사 근거가 남고, 견적서에는 현재 승인된 부품 번호와 수량이 남습니다.

What changes when the catalog changes?

  • Revised documents. Compare the SKU, revision and file hash. Index the replacement and retire the obsolete document without rebuilding the entire store.
  • Changes to the sales list. Refresh the sales approval and compatible parts for that model. The public demo includes a catalog snapshot at build time, so a new snapshot becomes live at deployment.
  • Latency and cost. Measure initial indexing, retrieval and model generation separately. With an index, every question can avoid retransmitting all PDFs. Retrieved passages still consume model input tokens and generation still takes time. Google File Search pricing ↗

The proposed AIK design combines document retrieval with sales catalog lookups. Explanations cite manufacturer evidence, and the quote identifies currently approved part numbers and quantities.
